# 動画の素材づくり

紹介動画やショート動画に使うゲームの映像は、ゲームが自分で遊ぶ「デモ再生モード」から作ります。画面収録で手早く撮る方法と、1コマずつ書き出してなめらかな動画にする方法の2つがあります。

## デモ再生モード

ゲームの URL に `?demo=1` を付けて開くと、タイトル画面から始まり、3つのパズルを最短の手順で解いて結末まで進みます（約90秒）。各パズルの最初に全体を見渡すカメラが回り、操作盤では Fold Mode の候補を順に見せてから変形します。デモのプレイはプレイログとして送られないので、改善ループのデータには混ざりません。

Mac で画面収録するなら、`https://mirrordimension.vercel.app/?demo=1&q=high` をフルスクリーンで開き、Command + Shift + 5 で収録します。音も一緒に録れます。URL に `&hud=0` を足すと画面の文字や枠が消えるので、字幕を後から自分で入れる場合に使えます。タイトルや各場面の長さは `&title=4&establish=3.5&browse=0.9&hold=1.2&end=4`（秒）で変えられます。

## 1コマずつ書き出す

`npm run video:capture -- video/demo.yaml` を実行すると、デモを1コマずつ進めながら撮影し、ffmpeg で MP4 にします。各コマでゲームの時間をちょうど 1/30 秒ずつ進めるので、描画が遅い環境でもカクつかず、好きな解像度で書き出せます。画面の文字のフェードや表示時間もゲームの時間に合わせて進みます。

準備として、Node.js 22.18 以上で `npm ci` を済ませ、`npx playwright install chromium` でブラウザを入れ、ffmpeg を入れておきます（Mac なら `brew install ffmpeg`）。別のターミナルで `npm run build && npm run preview` を動かしておくか、設定の `url` を公開中の URL にします。Mac では GPU で描画するので数分で終わります。GPU のない Linux のコンテナでは、540×960 で1コマ0.6秒ほどかかります。

設定は `video/demo.yaml` にまとめてあり、コピーして使い分けられます。

| 項目 | 内容 |
|---|---|
| `url` | 撮影するゲームの URL（ローカルのプレビューか公開中のサイト） |
| `out` | 書き出す動画のパス（`video/out/` は Git に入りません） |
| `size` | 動画の画素数。ショートは `[1080, 1920]`、授業の紹介動画は `[1920, 1080]` |
| `fps` | 1秒あたりのコマ数 |
| `quality` | 画質（`low`、`medium`、`high`） |
| `hud` | 画面の文字や枠を映すか |
| `uiScale` | 文字や枠の拡大率。省略すると、縦長はスマホ（幅360）、横長はノートPC（幅1280）と同じ配置になる |
| `crf` | 圧縮の強さ（小さいほど高画質で大きいファイル。18でほぼ劣化なし） |
| `maxSeconds` | 撮影を打ち切る長さ |
| `demo` | タイトルや各場面の長さ（秒）。URL の指定と同じ |

動画の隣には `<名前>.cues.json` ができます。各パズルが始まった時刻、変形した時刻と内容、結末の時刻が入っているので、字幕や効果音をその瞬間に合わせる編集に使えます。

## 改善の前と後を並べる

改善ループが反映する前の版を撮るには、前の版のコミットを別のフォルダに取り出してビルドし、別のポートでプレビューを動かして、設定の `url` をそちらに向けます。たとえば `git worktree add ../fold-city-before <コミット>` で取り出し、そのフォルダで `npm ci && npm run build && npx vite preview --port 4174` を実行して、`url: http://localhost:4174/` で撮影します。同じデモの手順で撮れるので、ヒントや誘導の違いを左右に並べて比べられます。

## 自分で用意する映像

映画の一場面などの自分で用意する映像は `video/local/` に置いてください。このフォルダは Git に入らないようにしてあります。他人の著作物を使った動画は、授業の提出の範囲にとどめ、Web に公開しないでください。
