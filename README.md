# FOLD / CITY

折り畳まれた都市を歩き、建築を折り直して道を作る、ブラウザで遊ぶ3D空間パズルです。プレイデータを集計し、Claude Code がステージの調整案を作り、自動で検証してから反映・デプロイする「学習する都市」の仕組みを持っています。筑波大学「メディアデザイン」の授業課題として制作しています。

## 遊び方

キーボードとマウスで遊びます。WASD で移動（Shift でダッシュ、Space でジャンプ）、マウスで視点、操作盤の上で E を押すと Fold Mode に入り、A / D で変形先を選んで E で実行します。R でそのパズルをやり直し、Esc でポーズです。第一区画は「最初の折り目」「パスキューブ」「フォールド・ゲート」の3つのパズルで、最短手数はそれぞれ1手・2手・3手です。URL に `?demo=1` を付けると、ゲームが自分で最後まで遊ぶデモ再生になります（動画の素材づくりは [video/README.md](video/README.md)）。

## 開発

Node.js 22.18 以上が必要です（TypeScript を Node でそのまま実行するため）。

```bash
npm ci
npm run dev        # 開発サーバー
npm test           # ソルバー・検証器・改善ループの単体テスト
npm run validate   # ステージの検証（解けるか、詰みがないか、設計意図を満たすか）
npm run build      # 型チェックと本番ビルド
npm run preview    # ビルドの確認（http://localhost:4173）
npm run e2e        # ブラウザで歩くテスト、デモ再生のテスト、ヒントと干渉の表示のテスト、レビュー用ショットのテスト（preview 起動中に実行。npx playwright install chromium が必要。画面が真っ白・真っ黒・単色だと失敗する）
npm run e2e:headed # レビュー用ショットを、ウィンドウを開いた Chrome の標準の描画設定で、画質（low・medium・high）と表示倍率（1・1.25・1.5）の9通りに描いて確かめる（preview 起動中に実行。ウィンドウが開くので npm run e2e には含まれない）
npm run video:capture -- video/demo.yaml   # デモを1コマずつ書き出して MP4 にする（ffmpeg が必要）
```

URL に `?debug=1` を付けるとテスト用のフック（`window.__fold`）が有効になり、`?q=low|medium|high` で画質を指定できます。

URL に `?shots=1` を付けると、美術レビュー用に8つの固定カメラのショットを撮れるモードになり（仮想クロックで動き、デモもテレメトリーの送信もなく、画質は `q=` がなければ `high`）、`window.__shots` が `ready()`（準備ができたら true）、`list()`（`title`・`s1-overview`・`s2-overview`・`s3-overview`・`s1-play`・`s2-play`・`s3-play`・`gate` の `{ id, label }`）、`show(id)`（その場面を整えて描き終えたら解決する Promise で、未知の id は reject）を公開し、同じビルドなら同じショットは見せる順番によらず同じ絵になります。Windows のヘッドレス Chrome は、標準の描画設定だと描画倍率が1でないときに画面が真っ白になるため、テストと `video:capture` は `--use-angle=gl` で起動します。背景の都市は区画ごとに折り方が変わります。どの区画でも、街路と建物を載せた一枚のシートを進行方向（+X）を軸にして左右から巻き上げるので、進むほど都市がプレイヤーを囲んで閉じていきます（第1区画は両側の壁が地平線へ開く峡谷 `horizon`、第2区画は地面が直角に折れて両側の壁になり、さらに折れて頭上の天井になり、空の細い切れ目を残す `fold90`、第3区画は進行方向を軸にした筒 `ring`）。区画を抜けると約4秒かけて次の形へ折れます（「演出の動きを減らす」では短いフェード）。仕組みは `src/game/foldcity/` にあります。確認用に、`?city=<名前>` で全区画を一つの形に固定でき（`horizon`・`fold90`・`ring`、および試作の `corner`・`ringx`・`warp`）、`?morph=s1-s2:0.5` で折れる途中（隣り合う区画、0〜1 の割合）を止めて見られ、`?morph=loop` で折り続けます（フレーム時間の計測用）。`?bgdebug=facing` を付けると、背景を種類ごとの単色で塗ります（視線がシートの法線から30度以内の「真上から見た」地面は赤、それ以外の地面は黄、真上から見た屋根は赤紫、それ以外の屋根は青、建物の壁は緑、遊ぶ場所は白、空は黒）。ショットごとの割合を数えて、背景が地図のように見えていないかを確かめるためのものです。`?bgdebug=range` は背景を距離で塗り分けます（カメラから200 mより遠い所は赤、近い所は緑）。遠い建物の窓のコントラストを測るときのマスクです。背景の光は都市のシートの面ごとに当てます（`src/game/foldcity/atmosphere.ts`）。どの面でも、低い主光がシートに沿って差し、その向きは世界の太陽をその面に投影した向きです。面が太陽を向くほど主光が強くなるので、峡谷の片側の壁は日向、反対側は日陰になり、床と天井はその中間で、黒くつぶれる面はありません。建物と並木の影は、シート座標の高さマップを主光の向きへたどって構造ごとに作る影のマップ（`shadow.ts`、2 m 刻み、1枚約1.9 MB。読み込み後に数フレームずつ計算し、地面は2枚を読んで折れる間は混ぜます）です。霞にほぼ沈んだ遠景は、開いた峡谷ではその先の空へ溶け、閉じた第2・第3区画では霞のままです（シートの両端に霞の面を置き、天井の切れ目にも距離に応じた霞を重ねるので、断面の形の空の窓は見えません）。切れ目の壁の上端は街区ごとに終わり、建物の屋根の線が空との境目になります。200 mより遠い建物の正面は、窓の格子をほぼ消して階ごとの淡い帯にします。`?sky=a1` は空の比較用の変種です（参考写真 A1 に寄せて、地平線の淡い帯から青への移り変わりを約16度まで延ばし、青の彩度を下げたもの。既定の空と光は変わりません）。`tests/e2e/budget.cjs` は各ショットのドローコールと三角形の数を予算と比べます。さらに `&ui=1` を付けると、8つのショットの後に UI の状態（`ui-fold`・`ui-fold-blocked`・`ui-hint`・`ui-pause`・`ui-controls`・`ui-clear`）が並びます。`&char=1` を付けると、最後に人物を近くから見る2つ（`player-front`・`player-back`）が加わります。人物のモデルは `art/blender/gen_character.py` が作る `public/assets/character/wanderer.glb` で、別のモデルと比べるときは `src/game/wandererAvatar.ts` の `WANDERER.url` を変えます（大きさ・向き・足元の位置は読み込み時にそろえます）。

## 構成

| 場所 | 内容 |
|---|---|
| `src/core/` | 描画に依存しないパズルの中核。ステージのコンパイル、接続の導出、干渉判定、ソルバー、検証器。ゲームと Node のツールで共有する |
| `src/game/` | three.js のゲーム本体。手続き生成の建築、背景都市、移動、カメラ、Fold Mode、音、テレメトリ |
| `src/stages/` | ステージデータ（`area1.json`）と調整用の数値（`tunables.json`）。改善ループが変更するのはここだけ |
| `api/` | Vercel Function。`telemetry.ts` はプレイログを受け取って Vercel Blob に保存し、`telemetry-export.ts` は改善ループにログを渡す（GitHub Actions の OIDC トークンで認証し、前日までのログを日ごとにまとめる） |
| `tools/ai/` | 改善ループの集計・判定・提案の検証・適用 |
| `tools/video/`、`video/` | デモ再生を1コマずつ書き出すツールと、その設定（`video/demo.yaml`） |
| `ai/` | エージェントへの指示（`prompts/`）、出力形式（`schemas/`）、改善履歴（`history/log.json`） |
| `art/blender/` | Blender（4.4.3）の Python スクリプトで生成するアセット（`gen_gate.py` → `public/assets/gate.glb`、`gen_floor.py` などの部材キット → `public/assets/kit/*.glb`、`gen_city.py` → 背景の都市の建物12種（オスマン様式の4〜12階の集合住宅、アール・デコの段状の量塊と塔、ドーム、鐘楼）`public/assets/city.glb`、`gen_cityprops.py` → 並木・広場の噴水と記念柱・大聖堂・橋脚の足元 `public/assets/cityprops.glb`、この2つの共通部分（建物の正面を描いたテクスチャと形の部品）は `city_kit.py`、全体の共通部分は `fc_kit.py`） |
| `art/textures/` | Poly Haven（CC0）から取得したテクスチャの原本（`node art/fetch-textures.mjs` で再取得できる） |
| `.github/workflows/` | `ci.yml`（テストとビルド）、`improve.yml`（毎日の改善ループ） |
| `docs/` | 設計書（`design/`）と公開・運用の手順（`SETUP.md`） |

## 改善ループ

ゲームは匿名のプレイログ（操作の回数・時間・おおまかな位置・アンケート）を送ります。GitHub Actions が毎日ゲームの API からログを受け取って集計し、新しいプレイがあれば Claude Code を非対話で起動します。Claude Code は集計結果とステージを読み、許可された範囲の変更（ヒントの時間や誘導の強さ、あらかじめ用意された配置の候補の選択）を提案ファイルに書き、検証コマンドで自分の提案を確かめます。その後、LLM を使わない別のジョブが提案を検証し直し、合格したときだけステージを書き換え、都市の改訂番号を上げてコミットし、デプロイします。改訂の内容はタイトル画面に表示され、`ai/history/log.json` に記録されます。

公開と運用の設定は [docs/SETUP.md](docs/SETUP.md)、設計の詳細は [docs/design/](docs/design/README.md) にあります。
