# FOLD / CITY

折り畳まれた都市を歩き、建築を折り直して道を作る、ブラウザで遊ぶ3D空間パズルです。プレイデータを集計し、Claude Code がステージの調整案を作り、自動で検証してから反映・デプロイする「学習する都市」の仕組みを持っています。筑波大学「メディアデザイン」の授業課題として制作しています。

## 遊び方

キーボードとマウスで遊びます。WASD で移動（Shift でダッシュ、Space でジャンプ）、マウスで視点、操作盤の上で E を押すと Fold Mode に入り、A / D で変形先を選んで E で実行します。R でそのパズルをやり直し、Esc でポーズです。第一区画は「最初の折り目」「パスキューブ」「フォールド・ゲート」の3つのパズルで、最短手数はそれぞれ1手・2手・3手です。URL に `?demo=1` を付けると、ゲームが自分で最後まで遊ぶデモ再生になります（動画の素材づくりは [video/README.md](video/README.md)）。

## 開発

Node.js 22.18 以上が必要です（TypeScript を Node でそのまま実行するため）。

```bash
npm ci
npm run dev        # 開発サーバー
npm test           # ソルバー・検証器・改善ループの単体テスト
npm run validate   # ステージの検証（解けるか、詰みがないか、設計意図を満たすか）
npm run build      # 型チェックと本番ビルド
npm run preview    # ビルドの確認（http://localhost:4173）
npm run e2e        # ブラウザで歩くテスト、デモ再生のテスト、ヒントと干渉の表示のテスト、レビュー用ショットのテスト（preview 起動中に実行。npx playwright install chromium が必要。画面が真っ白・真っ黒・単色だと失敗する）
npm run e2e:headed # レビュー用ショットを、ウィンドウを開いた Chrome の標準の描画設定で、画質（low・medium・high）と表示倍率（1・1.25・1.5）の9通りに描いて確かめる（preview 起動中に実行。ウィンドウが開くので npm run e2e には含まれない）
npm run video:capture -- video/demo.yaml   # デモを1コマずつ書き出して MP4 にする（ffmpeg が必要）
```

URL に `?debug=1` を付けるとテスト用のフック（`window.__fold`）が有効になり、`?q=low|medium|high` で画質を指定できます。

URL に `?shots=1` を付けると、美術レビュー用に8つの固定カメラのショットを撮れるモードになり（仮想クロックで動き、デモもテレメトリーの送信もなく、画質は `q=` がなければ `high`）、`window.__shots` が `ready()`（準備ができたら true）、`list()`（`title`・`s1-overview`・`s2-overview`・`s3-overview`・`s1-play`・`s2-play`・`s3-play`・`gate` の `{ id, label }`）、`show(id)`（その場面を整えて描き終えたら解決する Promise で、未知の id は reject）を公開し、同じビルドなら同じショットは見せる順番によらず同じ絵になります。Windows のヘッドレス Chrome は、標準の描画設定だと描画倍率が1でないときに画面が真っ白になるため、テストと `video:capture` は `--use-angle=gl` で起動します。背景の都市は区画ごとに折り方が変わります。どの区画でも、街路と建物を載せた一枚のシートを進行方向（+X）を軸にして左右から巻き上げるので、進むほど都市がプレイヤーを囲んで閉じていきます（第1区画は両側の壁が地平線へ開く峡谷 `horizon`、第2区画は地面が直角に折れて両側の壁になり、さらに折れて頭上の天井になり、空の細い切れ目を残す `fold90`、第3区画は進行方向を軸にした筒 `ring`）。区画を抜けると約4秒かけて次の形へ折れます（「演出の動きを減らす」では短いフェード）。仕組みは `src/game/foldcity/` にあります。確認用に、`?city=<名前>` で全区画を一つの形に固定でき（`horizon`・`fold90`・`ring`、および試作の `corner`・`ringx`・`warp`）、`?morph=s1-s2:0.5` で折れる途中（隣り合う区画、0〜1 の割合）を止めて見られ、`?morph=loop` で折り続けます（フレーム時間の計測用）。`?bgdebug=facing` を付けると、背景を種類ごとの単色で塗ります（視線がシートの法線から30度以内の「真上から見た」地面は赤、それ以外の地面は黄、真上から見た屋根は赤紫、それ以外の屋根は青、建物の壁は緑、遊ぶ場所は白、空は黒）。ショットごとの割合を数えて、背景が地図のように見えていないかを確かめるためのものです。`?bgdebug=range` は背景を距離で塗り分けます（カメラから200 mより遠い所は赤、近い所は緑）。遠い建物を見分けるときのマスクです。`?bgdebug=dist` は距離を100 m刻みの色で塗ります（赤・緑・青の3ビットで、0〜100 mが赤、100〜200 mが緑、…、600 m以上が白）。`?bgdebug=notrees` は並木だけを消します（影は残るので、付けたときとの差で並木の画素を取り出せます）。背景の光は都市のシートの面ごとに当てます（`src/game/foldcity/atmosphere.ts`）。どの面でも、低い主光がシートに沿って差し、その向きは世界の太陽をその面に投影した向きです。面が太陽を向くほど主光が強くなるので、峡谷の片側の壁は日向、反対側は日陰になり、床と天井はその中間です。空からの光は、建物の壁では足元ほど、地面では中庭と建物の足元ほど弱くして、通りと中庭を深い日陰にします（`bgCanyon`、`ground.ts` の `bgOcc`）。霞は距離の5乗で濃くなり（200 mで1 %未満、300 mで4 %、400 mで17 %）、閉じた第2・第3区画では470 mから先が2.2乗でゆるやかに濃くなります（600 mで51 %、700 mで63 %、900 mで82 %、1100 mで93 %。開いた峡谷は5乗のままで、600 mで76 %）。近くの都市は霞をかぶらず、遠くの都市だけが沈み、閉じた第2・第3区画の奥は縁のある円盤にならずに数百 mかけて霞へ消えます。都市の暗部に下限は置きません（以前の `toe` は既定で 0）。代わりに、トーンマッピング（Khronos Neutral）が暗部を二乗する分を都市だけ打ち消し（`untoe`）、日陰は空の光で照らします。このトーンマッピングは赤・緑・青から同じ量を引くので、暗い色ほど彩度が上がります（日陰の石が茶色に、日陰のスレートが濃い青になる）。都市ではこれも打ち消し、画面上の明るさは変えずに、彩度を場面の中での彩度に戻します（`chroma`）。空の光には形があります：シートから外を向く面（屋根、軒や窓台の上面）は全部、壁は約6割、シートの内を向く面（軒裏）は1割を受け、折れ上がったシートでは世界の空を見上げる面がさらに明るくなるので（`skyUp`）、日陰の壁でも軒の線・屋根の勾配・壁の向きが明暗で読めます。空の光の強さは、太陽に背を向けたシートと向いたシートで別に決めます（`skyShade`・`skySun`）。本当に暗いのは、日陰の通りの底と中庭（`occShade`）、建物の足元（`canyon`）だけです。建物と並木の影は、シート座標の高さマップを主光の向きへたどって構造ごとに作る影のマップ（`shadow.ts`、2 m 刻み、1枚約1.9 MB。最初の区画の分は読み込み中に、残りは読み込みの2秒後から1.5秒おきに1枚ずつ（1枚約20 ms）計算し、地面は2枚を読んで折れる間は混ぜます）。都市の配置の計算は、2つの GLB の読み込みと並行して進めます（配置はファイルを必要としないため）。都市は、シェーダーをフレームの外でコンパイルしてから（`compileAsync`）、地面、霞の面、建物の順に1つずつ場面に入れ、前のものが1度描かれてから次を入れます（グラフィックスドライバーがシェーダーを仕上げるのは最初に描くときで、地面のものは約0.6秒かかるため、1フレームにまとめず、ゲームが準備完了（`ready`）になる前に済ませます）です。霞にほぼ沈んだ遠景は、開いた峡谷ではその先の空へ溶け、閉じた第2・第3区画では霞のままです（シートの両端に霞の面を置き、天井の切れ目にも距離に応じた霞を重ねるので、断面の形の空の窓は見えません）。切れ目の壁の上端と、霞の先で空へ溶ける所は、街区ごとに終わり（建物は街区ごと残るか消えるかです）、建物の屋根の線が空との境目になります。建物の正面の窓は、遊ぶ場所（`plan.ts` の `PLAY` の箱。カメラはこの中を動きます）からの距離で薄くします。歩廊の真下の街は窓を残し（そこでも3割だけ階の色へ寄せます）、箱から45〜105 mで窓の格子をほぼ消して、正面を階ごとの淡い帯にします（窓のある帯だけで、スレート・亜鉛・切石・ガラスの面の模様は残します）。プレイ視点が見通す壁（カメラの120〜250 m先）は帯だけになります。同じく箱から60〜160 mで、建物の明るさ（スレート・ガラス・屋根窓・石）を中間の明るさへ最大90 %寄せて、遠い壁のコントラストを落とします（歩廊の下でも2割。寄せるのは明るさだけで、色みは残すので、石灰岩は暖かく、スレートは青灰色のまま霞に入ります。建物ごとの明るさの違いも残します。地面と遠景の街並みには掛けません）。素材の色は、暖かい石灰岩と、彩度の低い青みのある灰色のスレート・亜鉛・ガラスです（参考写真 A1・A2 の屋根の色。以前の色から明るさを変えずに彩度だけを下げたもので、スレートと亜鉛は6割、ガラスは7割、石は8.5割）。軒・笠石・屋根窓・煙突は正面の石灰岩と同じ色みで、屋根の上に黄土色の部材は置きません。ドームは鉛の板の継ぎ目ごとに亜鉛の畝が立つ一色の金属で、2色の縞にはしません。`?farwin=1` は比較用の変種で、窓をコントラストを落として遠くまで残します。建物の詳しいモデルは、遊ぶ場所から340 m以内に立つものに使います。詳しいモデルは、プレイ視点の距離で読める形（屋根の輪郭）で作ってあります：急な下の勾配と緩い上の勾配のマンサード屋根、その境目の亜鉛の帯、1間ごとの屋根窓の列、棟の脇に不ぞろいに立つ煙突、影の帯の上に大きく張り出した軒とバルコニーの床、最上階が引っ込んだ屋階、両端が1階高いパビリオン、アール・デコの段状の頂部。正面は参考写真 A2 にならって形で作ってあります：大きな切石（1つずつ色が少し違う）を積んだ太い柱が約7 mおきに立ち、その間に、0.6 m引っ込んだ背の高いガラスの開口が1つか2つ（1階と、その上の全階をまとめた1つ）。窓を1間ごとに並べた格子のテクスチャは遠景用モデルだけに使います。長い建物は正面の中央が少し張り出して軒の上まで石の塊として立ち上がり、マンサード屋根の両端には煙突をまとめた段状の妻壁が立ち、屋根の妻側にも屋根窓があるので、屋根の端が空に対して一本の直線になりません。並木は大通りの縁に不ぞろいに立ちます（間隔8〜20 m、ところどころ20〜50 m空き、3割ほどは若い木で小さい）。葉の彩度は街の石と同じくらいまで落としてあります。遊ぶ場所から約265 mより遠くには立てません。石の尖塔のある建物（鐘楼・大聖堂）は、遊ぶ場所の長さの範囲と、その手前120 m・先360 mには立てず、同じ敷地に尖らない建物を置きます（ドームとアール・デコの塔は手前・先とも120 m）。塔の家・アール・デコの塔・ドームの頂部は尖らせていません。両側の壁には、遊ぶ場所の先およそ270 mに、決まりで1つずつ目印の建物が立ちます（片側はアール・デコの段状の塔、もう片側はドーム。どの区画の形でも立ちます）。第1区画の峡谷の奥（700 mより先、シートが平らになる所）には遠景の街並みが立ちます（`skyline.ts`：5列、長い屋根と段状の量塊の上に塔・ドーム・大聖堂が抜ける。遠景用モデルを2.5〜5倍にして直立させ、列ごとに濃い霞の中に置き、足元は霞に消します。峡谷が閉じる折りの間に霞へ消えます）。地面にノイズの模様は使いません（本人の決定）。通りの細部は実物で描きます（地面のシェーダー）：2色の石の帯を、目地をずらして並べた敷石1枚ずつに分けた舗装（帯の濃淡は以前の4割で、1枚ごとに石の色が少し違い、帯の濃さは街区ごとに違います。以前は帯だけだったので、離れると縞に見えました）、敷石の目地、淡い縁石、駐車帯の石畳、車線の線（中央線、駐車帯の線）、交差点ごとの横断歩道と停止線、路肩に停まった車とその影（1台が2ピクセルより小さくなる所では消えます）、車線を走る車、大通りの中央の植え込み、芝を縞に刈った公園、街区の中庭の庭（砂利の小道のあいだの芝・植え込み・敷石の区画）。舗装の模様は、歩廊の下の街を上から見るときのもので、遊ぶ場所から110〜240 mで消え、地面を斜めに見る所（遊ぶ場所の両側の壁）と太陽に背を向けた地面では薄くなります。敷石1枚ごとの色・目地・走る車・中庭の庭は、地面を上から見る所にだけ描きます。開いた峡谷（第1区画）では、舗装の模様・走る車・庭を4.5割に抑えます（カメラを真横に向けると壁を正面から見ることになり、模様が地図のように目立つため。`canyonPave`）。屋根も、建物を真上に近い向きから見る所（閉じた第2・第3区画）では、スレート・亜鉛板・屋上の敷石のテクスチャの濃淡を強めて描きます（`grain`）。遊ぶ場所から横に見る屋根は塗ったままの静かさです。地面が遠くの空へ消えるときは、建物より少し先に消えるので、空との境目は街区のまっすぐな縁ではなく建物の輪郭になります。遊ぶ場所から300〜430 mより遠い建物は、高さを38 mまでに抑えます。空は参考写真 A1 に寄せたものが既定です（地平線の淡い帯から青への移り変わりを約16度まで延ばし、青の彩度を下げ、帯の途中では赤、緑の順に早く抜いて、桃色と青の中間が薄紫ではなく淡い青になるようにしたもの。変わるのは見える空だけで、空が与える光は以前の空から作ります）。`?sky=old` は比較用で、以前の空（帯が約9度で終わり、青が濃い）を表示します。`?bgtune=skyShade:1.8,calm:0.4` のように書くと、背景の都市の霞・空の光・敷石の濃さ・窓の薄れ方などの数値をビルドせずに試せます（キーは `src/game/foldcity/atmosphere.ts` の `TUNABLE`）。`tests/e2e/budget.cjs` は各ショットのドローコールと三角形の数を予算と比べます。さらに `&ui=1` を付けると、8つのショットの後に UI の状態（`ui-fold`・`ui-fold-blocked`・`ui-hint`・`ui-pause`・`ui-controls`・`ui-clear`）が並びます。`&char=1` を付けると、最後に人物を近くから見る2つ（`player-front`・`player-back`）が加わります。人物のモデルは `art/blender/gen_character.py` が作る `public/assets/character/wanderer.glb` で、別のモデルと比べるときは `src/game/wandererAvatar.ts` の `WANDERER.url` を変えます（大きさ・向き・足元の位置は読み込み時にそろえます）。

背景の都市の建物は、質感と汚れを持つ建物（`public/assets/buildings.glb`、`art/blender/gen_buildings.py`）です。上の段落のうち、窓のテクスチャの薄れ方（`winNear` など）と「詳しいモデル」の形の説明は、比較用の以前の建物（`?bldg=old`、`city.glb`）のものです。距離による明るさの寄せ方、素材の色、並木、目印の建物の置き方、遠景の街並み、地面は今の建物にも当てはまります。

- 建物の単位：79種類で、それぞれ近景用と遠景用の2つのモデルがあります。オスマン様式の家が2〜4軒並ぶ列が49種類（長さ26〜53 m、高さ11〜47 m。家ごとに階数・軒の高さ・石の色・正面（2種類）・屋根（マンサード、急勾配のパビリオン屋根、2段のマンサード、テラスの奥に引っ込んだ屋階、パラペットのある陸屋根）・屋根窓の並び・煙突が違い、端が煙突をまとめた妻壁のものや、角にスレートのドームの円塔が付くものがあります）、段状の石の頂部を持つ塔の家が5種類、アール・デコの量塊が12種類（柱とガラスの帯のものと、石の壁に窓が並ぶものが半々）、目印の建物が5種類（アール・デコの大きな館と塔、鐘楼、ドーム、大聖堂。それぞれ高さが約半分の低い版もあります）、広場の記念柱・噴水と橋脚の足元です。
- 敷地への当てはめ：配置の計算（`layout.ts`・`morphplan.ts`）は以前のまま、敷地ごとに箱（長さ・奥行き・高さ）を決めます。その箱に、同じ系統の単位のうち縦横の比がいちばん近いものを選んで合わせます（`models.ts` の `pickUnit`、`unitpick.ts`）。窓や階の比は、長さ・高さとも8割の建物で ±10 % 以内、99 % で ±20 % 以内に収まり（残りは主に、家の列を置いた背の高いアール・デコの敷地で、最大で約 1.5 倍に伸びます）、試作にあった 0.71 倍などの引き伸ばしはありません。同じ街区で隣り合う敷地には別の単位を選び、合う単位が1つしかないときは半回転させるので、同じ建物が同じ向きで続けて並ぶことはありません。アール・デコの敷地の 45 % と塔の家の敷地の 30 % には、家の列を置きます（配置の計算が長さだけで選ぶため、以前は壁の3分の1近くがアール・デコの板でした）。構造ごとに敷地の高さが変わるので、単位も構造ごとに選び、折れる途中の半分で切り替えます。影のマップも、置いた単位の形から作ります。
- 素材：512×256 ピクセルの繰り返しテクスチャ8枚（石灰岩の切石、正面2種類、スレート、亜鉛、アール・デコのガラス、漆喰、大きなアーチ窓の正面）を1枚の配列テクスチャにまとめ、都市全体を1つのマテリアル・1回の描画で描きます（GPU 上でミップマップ込み約 5.6 MB。以前の 512×512 のアトラスは既定では読み込みません）。Poly Haven（CC0）の写真から `gen_buildings.py` が作り、窓・店先・扉・鎧戸・窓台は同じスクリプトが描き込みます。各テクスチャのアルファには、汚れが出やすい場所のマスクが入っています。
- 窓：近くでは、枠・まぐさ・窓台・ガラスのある開口の列として描き、遊ぶ場所から 60〜160 m で、タイルの各行の平均色（階ごとの帯）へ寄せます（`texWin`・`texWinFar`・`texBand`）。遠くでは点ではなく帯になります。
- 汚れ：軒・バルコニー・窓台の下の雨だれ、1階の足元の汚れ、軒先と煙突の頂部の煤を、頂点ごとの値として形から決め、マスクと掛け合わせて表示します。建物ごとに、汚れの強さ、汚れの出る場所（建物全体にかかる広いしみ）、石と屋根の色みが違います（`texDirt`・`texDirtBase`・`texDirtOwn`）。日陰の壁では、黒つぶれを増やさないように、暗部の下限を置き（`texDark`・`texDarkShade`）、石と急勾配の屋根を少し持ち上げます（`texToneShade`）。
- 遠景用モデルは同じ配列テクスチャと同じ色・汚れの計算を使い、形を省いたものです（屋根窓・バルコニーの床・煙突の先を省略）。遊ぶ場所から 340 m の境目で近景用と入れ替わり、700 m より先の遠景の街並みにも使います。
- 確認用：`?bldg=old` は以前の建物を表示します。`?bgdebug=unit0`・`unit1`・`unit2` は、建物を単位の番号の3ビットずつで塗り分けます。`python -I tools/units-count.py <3つの撮影を入れたフォルダー>` で、ショットごとに見えている単位の種類を数えます（150 ピクセル以上を占めるもの）。`BASE_URL=http://localhost:4173/ node tools/units-view.cjs out.png [単位の名前…]` は、単位だけを空を背景に並べて描きます。
- 作り直し：`node <game3d>/scripts/blender.mjs art/blender/gen_buildings.py -- --out public/assets/buildings.glb --table src/game/foldcity/units.ts`（単位の寸法の表 `units.ts` も同じスクリプトが書き出します）。

## 改善ループ

ゲームは匿名のプレイログ（操作の回数・時間・おおまかな位置・アンケート）を送ります。GitHub Actions が毎日ゲームの API からログを受け取って集計し、新しいプレイがあれば Claude Code を非対話で起動します。Claude Code は集計結果とステージを読み、許可された範囲の変更（ヒントの時間や誘導の強さ、あらかじめ用意された配置の候補の選択）を提案ファイルに書き、検証コマンドで自分の提案を確かめます。その後、LLM を使わない別のジョブが提案を検証し直し、合格したときだけステージを書き換え、都市の改訂番号を上げてコミットし、デプロイします。改訂の内容はタイトル画面に表示され、`ai/history/log.json` に記録されます。

公開と運用の設定は [docs/SETUP.md](docs/SETUP.md)、設計の詳細は [docs/design/](docs/design/README.md) にあります。
