# v0.5 の仕組み：コア（`src/core`）の規則

[README の v0.5](README.md) で決めた4つの動き（糸で渡る、把手、乗る、時計仕掛け）を、ソルバーと検証器が扱える形にしたものの仕様。対象は `src/core` だけで、ゲーム側（アニメーション、入力、HUD）は含まない。どの規則も「パズルの状態（と、書かれている場合はプレイヤーの立つマス）だけで決まる関数」なので、ソルバー、ヒント、あとから作るランタイムが同じものを使う。

README の「アンカー」は、コードでは **tether**（輪）と呼ぶ。

試作のステージは `tests/fixtures/proto-core.json`（メカニクスごとに1区画）、テストは `tests/v05core.test.ts`。

## 1. データ

追加はすべて省略可能で、`area1.json` は変えずに通る。型は `src/core/types.ts`。

### 糸（tether）

```json
{ "id": "t_ra", "type": "tether", "at": [2, 3, 0], "params": { "facing": "E", "span": 8 }, "group": "g_x" }
```

- 歩けるタイルは持たない。セル `at` の `facing` の辺の真ん中に、そのセルの床から 1.6 m 上に付く輪。
- 着地するマスは自分のセル。そのセルは、別のモジュール（タイル、橋など）の歩けるタイルでなければならない。
- `group` を付けると、モジュールの変換に従って動く。世界でのセル、向き、輪の位置は状態で変わる。
- `span` は届くセル数（省略は 8）。2以上の整数。

### 把手（handle）

```json
{ "id": "h1", "at": [2, 3, 18], "height": 2, "controls": "g_hb", "reach": 3, "axis": "y", "label": { "ja": "…", "en": "…" } }
```

- `StageFile.handles?: Handle[]` と `PuzzleSection.handles?: Id[]`。
- 把手の点は世界に固定で、グループとは一緒に動かない。点はセル `at` の中央、そのセルの床から `height` m（省略は 2）。
- `reach` はセル数（省略は 3）。`axis` は向きグループ（`orientation`）の把手だけが使い、必須。
- 把手の `id` は操作盤の `id` と重ならない（`mustUse` が両方を同じ名前の空間で指すため）。

### 時計仕掛け（auto）

```json
{ "id": "g_clock", "kind": "states", "…": "…", "auto": { "periodMs": 4000, "dwellMs": 1800 } }
```

`kind: 'states'` のグループだけ。時計が刻むたびに、グループは `states` を1つ進み、最後の次は最初に戻る。`dwellMs` は、各状態で止まっている時間。

### アクション

```ts
type Action = /* これまでどおり：操作盤の set と turn */;
interface StepAction { handle: Id; group: Id; kind: 'step'; dir: 1 | -1 }
interface WaitAction { kind: 'wait'; section?: Id }
type PlayerAction = Action | StepAction | WaitAction;
```

`Action` は変えていない（`src/game` が `a.console` を前提にしているため）。新しい2つを足した和が `PlayerAction`。`wait` の `section` は、どの区画の自動グループを進めるか。省略すると、ステージのすべての自動グループが進む。`actionKey` は `h1:step+1`、`h1:step-1`、`wait`。

## 2. 規則（`compile.ts`）

### 糸のつながり

状態 s で、糸 A と B は次のすべてを満たすとつながる。

1. 世界での向きが、どちらも水平。
2. B の向きが A の向きの反対。
3. B のセル − A のセルが、A の向き f の k 倍と上下の差の和（k は整数）。2 ≤ k ≤ min(span_A, span_B)、上下の差は 2 段まで。
4. B は、A の視線（f の方向）で最初の糸。視線上にある糸は、横にずれず、上下 2 段以内のもの（向き、span、着地の可否は問わない）。同じ距離に複数あれば、どれも最初。
5. 両方の着地マスが、s で歩ける。
6. 2つの輪を結ぶ線分に、世界の箱がない。両端の着地マスのモジュールだけは除く。約 0.25 m ごとに BoxHash で調べる。

つながりは両方向。A の視線が B を見つけても、B の視線が A を見つけてもよい。

`computeWalkMap` は、つながりを着地マスの間の辺として足し、領域をつなぐ。`WalkMap.links: { a: Id; b: Id; from: string; to: string }[]`（`a`、`b` は糸のモジュール id で、`from`、`to` は着地マスのキー）。糸が2本未満のステージでは何も計算しない。

`walkPath` はつながりも辺に使う。つながりでの移動は1歩で、隣のマスではないマスに着く（どれがつながりかは `wm.links`）。`walkLinks(wm, from, targets)` は、歩きで渡らなければならないつながりの最小の数を返す。

### 把手の届く範囲

`handleReach(handleId, s): string[]` は、状態 s で把手を使えるマスのキー（歩けるマスのうち、次のすべてを満たすもの。並びはキーの順）。

- 把手のセルまでの水平のユークリッド距離が `reach` セル以下。
- 上下の差が 1 段以内。
- 目の高さ（そのマスの床 + 1.5 m）から把手の点までの線が、世界の箱に遮られない。把手が操作するグループのモジュールは除く。

`handleActions(handleId, s): { action: StepAction; blockedBy: string[] }[]` は把手のステップ（`blockedBy` は `sweepBlockers` と同じ。空なら動かせる）。

- 状態グループは、`states` の隣のインデックスへ ±1。端を越えるのは、`states` が4つの違う四分の一回転の値（4で割った余りが 0, 1, 2, 3）を持つときだけで、このとき最後の次は最初（最初の前は最後）。それ以外は端を越えるステップがない。
- 向きグループは、`axis` まわりに四分の一回転ずつ、どちらにも（操作盤の `turn` の quarters 1 と 3 と同じ）。

### プレイヤーを含む動き

`motionOutcome(s, action, playerCell): MotionOutcome` は、プレイヤーが `playerCell` に立っているときに、アクションがどうなるか。

```ts
type MotionOutcome = { ok: true; cell: string; ride: boolean } | { ok: false; blockedBy: string[] };
```

- モジュールの掃引は今までどおり（`sweepBlockers`）。1つでもあれば `ok: false`。
- プレイヤーの立つタイルが動くグループのモジュールなら、プレイヤーは**乗る**。
  - 体（タイルの上の 0.8 × 1.8 × 0.8 m の箱）がグループと一緒に回り、その掃引が、グループに入らない世界の箱にぶつからない。体の点は 0.3 m 間隔、掃引の角度は、体の点が1刻みで 0.25 m を超えて動かない細かさ。
  - 立っているタイルが、目標の状態で、同じモジュールの上向きの歩けるタイルとして同じマスの持ち主になっていること。その新しいマスが `cell`。回転の中心のタイルのように、同じマスのままでも乗ったことになる（`ride: true`）。
  - 満たさないときは、`blockedBy` に `'player'` が入る。
- 乗らないとき、体は動くグループの点に対する動かない障害物で、ぶつかると `'player'`。目標の状態でも立っているタイルが（同じモジュールの同じタイルで）残っている必要がある。プレートが消えるとき（`area1` のプレートなど）、足場が消えるので `'player'`。
- 操作盤のアクションでは、体の検査をしない（操作盤の立ち位置の箱が体の代わりをする）ので、`area1` の操作盤の結果は変わらない。

`waitOutcome(s, playerCell, sectionId?)` は、時計が1回刻むとき（その区画のすべての自動グループが同時に1歩進む）の同じ結果。`motionOutcomes(s, action, cells)` は、複数のマスについての同じ検査をまとめて返す。

`apply(s, a)` は `step` と `wait` を扱う。`wait` は `autoGroups(sectionId?)` の各グループを1つ進め、端で戻る。

## 3. ソルバー（`solver.ts`）

- ノードは今までどおり `状態#領域`。
- 操作盤のアクションは今までどおり（プレイヤーは操作盤のマスにいて、動作の後もそこにいる）。
- 把手のステップは、その領域のうち把手の届くマスのどこからでも行える。待つは、領域のどのマスからでもよい。立つマスごとに結果は1つ（乗る、そのまま、ブロック）。違う次のノードの数だけ辺ができる。同じ次のノードに行ける立ち位置が複数あれば、乗らないほうを先にする。
- 辺の費用は、待つが 0、ほかが 1（0-1 幅優先）。`optimal` は、プレイヤーのアクション（操作盤と把手）の最小の数。待つ回数は含まない。
- 行き止まりは今までどおり：到達できて、そこからゴールへ行けないノード。

`SolveResult` は今までの `optimal, plan, explored, deadEnds, firstMoves` に加え、次を持つ。

- `moves: PlanMove[]`：最適な計画の全体。`{ action, key, at, to, ride, cost }`。`at` は立つマス、`to` は動作の後に立つマス。
- `waits`、`links`、`rides`：その計画の待つ回数、歩きが渡らなければならない糸の数（開始から各立ち位置、最後の立ち位置から出口まで）、乗った回数。
- `plan` は今までどおり**操作盤のアクションだけ**を並べる（`area1` では全体と同じ）。把手か時計仕掛けのある区画では、全体は `moves`。
- `firstMoves` は、操作盤のほか把手のステップと `wait` も含み、`penalty = その動作の費用 + そこからの最適 − 最適`。

そのほか：`nextMove(cs, sectionId, state, cell)` は、最適な計画の次の動作（種類を問わず、立つマスつき）。`nextAction` は今までどおり操作盤のアクションの先頭。`remainingActions` は、残りのアクション数（待つは数えない）。`reachableNodes(cs, sectionId)` は、到達できる状態と、そのとき立てる領域（検証器が使う）。`SolveOptions.disabledConsoles` は、操作盤と把手のどちらの id も受ける。

## 4. 検証器（`validate.ts`）

新しい規則：

| 規則 | 重さ | 内容 |
|---|---|---|
| T1 | 警告 | どの到達できる状態でも一度もつながらない糸 |
| T2 | 誤り | 糸の着地マスが、初期状態で歩けない |
| H1 | 誤り | どの到達できる状態でも、届くマスがない把手 |
| H2 | — | `mustUse` は把手も指せる（`mustUse` が区画の操作盤か把手でなければ S2、把手なしで最適に解ければ L4、使われない把手は L5 の警告） |
| C1 | 誤り | 自動の1歩が、到達できる状態で、そのグループに乗っていない歩けるマスのプレイヤーの体を通る（足場が消えるのも同じ）。時計はプレイヤーのために止められない |
| C2 | 誤り | 自動の1歩が、別のモジュール（や操作盤の立ち位置）に妨げられる。詰まり |
| C3 | 警告 | 自動の1歩で、乗っているプレイヤーが落ちる。ランタイムは、最後にいた動かないモジュールのマスに戻す |
| C4 | 誤り | 1つの区画の自動グループで `periodMs` が違う |
| C5 | 警告 | `dwellMs` が 900 未満 |

「到達できる状態」は、ソルバーが区画ごとに探索したノード（状態と領域）。C1〜C3 は、そのノードの領域のマスについて調べる。T1 は、すべての区画の状態と初期状態の和集合で調べる。ほかに、S2 が把手と自動グループの形（未知のグループ、向きグループの軸、`periodMs > 0`、`dwellMs >= 0`、2状態以上）を、S3 が糸の `facing` と `span` を調べる。

区画の指標（`SectionMetrics`）に、最適な計画の `waits`、`links`、`rides` を足した。

## 7. 仕様で決めたこと（あいまいだった点）

- `Action` は変えず、`PlayerAction` を新しくした。`src/game` の `a.console` などが、型の広がりで壊れないため。そのため `SolveResult.plan` と `nextAction` は、操作盤のアクションだけを返す。**把手か時計仕掛けのある区画では、`plan` の長さは `optimal` より短いことがあり、`nextAction` は「次の」動作ではないことがある。**ゲーム側は `moves` と `nextMove` へ移る必要がある。
- `wait` に任意の `section`、`waitOutcome` に任意の3つ目の引数を足した（どの区画の自動グループを進めるかを、アクションと関数が知るため）。
- `handleActions` は、操作盤の `consoleActions` と同じ `{ action, blockedBy }[]` を返す。
- 糸の「最初の糸」は、視線上で上下 2 段以内のものだけを数える。同じ距離のものは、どれもつながる。A の視線でも B の視線でも見つかればつながる。向きグループなどで転がった糸も、世界での向きが水平ならつながる（上向きかは問わない）。
- `'player'` は、体が掃引に当たることのほか、立っているタイルが目標の状態で消えることも指す。
- 複数の自動グループが同時に動くとき、それぞれは、ほかのグループを動かない状態として掃引する。乗っている人の体は、別のグループの動きとは照らし合わせない。
- 検証器の「到達できる状態」は、ソルバーが探索した範囲（`maxNodes` は 20000）。

## 8. ランタイムが知っておくこと

- 動きは `motionOutcome`／`waitOutcome` と同じものを使う。乗るときは `cell` が行き先のマス、`ok: false` で `'player'` があれば、プレイヤーを最後にいた動かないタイルのマスに戻す（状態は変えない）。
- 時計は `auto.periodMs` ごとに `{ kind: 'wait', section }` を適用する。`dwellMs` は止まっている時間。途中で止められない。
- 糸の移動は `wm.links` を見る。歩きの経路は `walkPath`。つながりは隣ではないマスへの1歩になる。
- 把手を使う位置は、`handleReach` に入っているマスで、その領域に立っているとき。ヒントは `nextMove`（`at` が立つマス）。
- ゲーム側の `solveSection(...).plan`、`nextAction`（`demo.ts`、`shots.ts`、`game.ts`、デバッグ用の `solve`）は、新しい区画を出す前に `moves`、`nextMove` に移す。
- `kitMeshes.ts` の `tether` は、メッシュなし（輪を描くのはランタイムの仕事）。

## 9. ゲーム側の動き（`src/game`）

§8 のとおりに、糸で渡る・把手で回す・乗るを遊べるようにした（時計仕掛け、落ちたら戻る、タイムトライアルは次の作業）。試作は `?stage=proto`（`src/stages/proto.json`）。

- **ステージの選び方**：`?stage=<名前>` は `src/stages` のファイル名。既定は `area1`、知らない名前は警告を出して `area1`（`src/game/stageSelect.ts`）。tunables.json に項目のない区画は `DEFAULT_SECTION_TUNABLES`（ヒント 40 秒と 100 秒、光の柱 0.5）を使う。`npm run validate` は、tunables を既定のステージ（`area1`）の区画にだけ求める。
- **糸**（`swing.ts`、`movement.ts`）：着地マスに立つと、向かいの輪へシアンの糸が見え、「Space 渡る」と出る。Space で弧を描いて渡り、向かいのマスの真ん中、その床の高さにぴったり着く。時間は 0.45 秒＋1 マスにつき 0.06 秒（「演出の動きを減らす」では 0.3 秒＋0.04 秒で、弧は 1/12 までの浅さ、カメラの揺れもなし）。弧は、輪から輪の間だけ弦の下へ弦の長さの約 1/3 垂れ（上りは弦の上へ 15 %持ち上がる）、着地マスの中は床の高さを走る。カメラが向いている向きに近い糸を選ぶ。
- **連鎖**：渡っている最後の 40 %（60 %から）で Space を押すと、着地マスにほかの糸（来た糸は除く）があれば、着地せずに続けて渡る。押した時点の位置と速さを保って、次の弧がその速さで出る。HUD に「連鎖 ×n」。
- **把手**（`movement.ts`）：届く範囲（`handleReach`）にある把手のうち、カメラの向きに最も近いものが光り、「Q / E 回す」と、あれば今の姿の名前が出る。Q は −1、E は +1。操作盤のマスの E は Fold Mode（操作盤が勝つ）。`motionOutcome` に立っているマスで尋ねて、通れば足場がfold-feel の曲線（`foldFeel.ts`）で実時間に回る。通らなければ短い揺れ、邪魔するものが赤く光り、Fold Mode のパネルと同じ名前で「干渉しています：…」。自分の足場や体が当たるときの名前は「あなたの立ち位置」。
- **回っている間の歩き**：`walkWhileMoving` が、回す前の地図と回した後の地図の両方に含まれる部分だけを返す（タイルは `motionOutcomes` が「そのままいられる」と言ったものだけ、辺は両方で開いているものだけ、糸は両方にあり、輪が回るグループにないものだけ）。回っている間は、その地図の上を歩く。回ったあとにどこに立っていても、ソルバーが数えた領域にいる。回っている間は、糸で渡ることも、次の把手も、操作盤も使えない（R だけは、回りを止めてパズルをやり直す）。
- **乗る**：結果が乗るなら、プレイヤーはグループの回転そのもの（軸の四元数）に運ばれ、入力は止まり、カメラが追う。降りるのは `outcome.cell` で、グループに対して同じ向き。
- **テレメトリー**：`swing`（`from`、`to`、`chain`）、`handle_step`（`handle`、`dir`、`ok`、`blockedBy`、`cell`）、`ride`（`handle`、`from`、`to`）。ステップの `actionKey` は `+` を含み `SHORT` に弾かれるので、`handle` と `dir` で送る。`src/core/telemetry.ts` と `api/telemetry.ts` の両方に足してある。プロトタイプのステージは `?telemetry=1` のときだけ送る。
- **ヒントとデモ**：`nextMove`／`moves` を使う。把手のステップは「光っている把手を探してみよう」「『…の把手』のそばで E を押して回してみよう」、待つは「少し待ってみよう」。デモは糸の区間でカメラをその向きにして Space を押す。
- **時計仕掛けのための足場**：`Game.lastSolid`（最後に立っていた動かないモジュールのマス）は追っている。まだないもの：時計（`periodMs` ごとの `wait`）、複数グループの同時アニメーション（`World.startAction` は1グループ）、乗っている人が降りられないときの戻し、`dwellMs` の間の「待つ」の表示。
